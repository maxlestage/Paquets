# Quick start

In this tutorial you build **Notebook**, a small app with a home page, a form, a database and a JSON API, then you test it. It takes about ten minutes and assumes only that Rust and the `paquets` command are installed (see [Installation](installation.md)).

## 1. Create the project

```sh
paquets new notebook --minimal
cd notebook
```

`--minimal` creates a project with a single source file, `src/main.rs`, and no islands, so you don't need any WebAssembly tool for this tutorial. Without `--minimal`, you also get a `src/lib.rs` with an interactive counter (see [Islands](islands.md)). Both kinds of projects contain the same deployment files; [Project structure](project-structure.md) describes them.

## 2. Run it

```sh
paquets dev
```

The first run compiles every dependency, which takes a few minutes. Later runs only recompile your code. When the server is ready, it prints:

```text
📦 Paquets · http://localhost:3000
   database: memory · security: on (10 guards) · islands: none
```

Open http://localhost:3000 in your browser: you see the starter page of the project. The second line tells you that the database is in memory, that the security shield is active with its 10 guards, and that the project has no islands.

Every request then prints one line, such as `GET / 200 0.339 ms`. Stop the server with `Ctrl+C`.

> [!TIP]
> `paquets dev` is `cargo run` plus the build of the islands when the project has some. In a minimal project, `cargo run` does exactly the same thing.

## 3. Write the home page

Replace the content of `src/main.rs` with this program:

```rust
use paquets::prelude::*;

/// The home page.
async fn home(_req: Request) -> Page {
    Page::new("Notebook")
        .description("My notes, in Rust.")
        .body(html::main().child(h1().text("📒 Notebook")))
}

fn app() -> App {
    let mut app = App::new();
    app.get("/", home);
    app
}

fn main() -> std::io::Result<()> {
    app().run()
}
```

Restart the server (`Ctrl+C`, then `paquets dev`) and reload the page. Let's read the program from the bottom:

- `main` builds the app and runs it. `run()` blocks until you press `Ctrl+C`.
- `app()` creates the application and declares its routes. Building the app in its own function lets the tests use the very same app, as you'll see in step 8.
- `app.get("/", home)` says: for a `GET` request on `/`, call `home`.
- `home` is a **handler**: an `async` function that receives the request and returns a response. Here the response is a `Page`, a complete HTML document with a title, a description for search engines and social networks, and a built-in theme.
- The body is a **view** built with one function per HTML tag: `h1().text("📒 Notebook")` is `<h1>📒 Notebook</h1>`.

> [!NOTE]
> Why `html::main()` and not `main()`? In this file, the name `main` is already taken by the program's `main` function. The `<main>` tag is therefore written `html::main()` here. See [Pages](pages.md#the-main-tag-in-mainrs).

## 4. Add a route with a parameter

Add this route in `app()`, after `app.get("/", home);`:

```rust
app.get("/hello/:name", |req: Request| async move {
    format!("Hello {}!", req.param("name").unwrap_or("you"))
});
```

Restart and open http://localhost:3000/hello/Ada: the page says `Hello Ada!`. The `:name` segment of the path is a parameter, read with `req.param("name")`. This handler is a closure instead of a named function, and it returns a `String`, which becomes a plain text response. See [Routing](routing.md) and [Requests and responses](requests-responses.md).

## 5. Store notes in a database

Add a **model** at the top of the file, after the `use` line:

```rust
/// A note: a table of the database, also sent and received as JSON.
#[model]
struct Note {
    id: i64,
    text: String,
    done: bool,
}
```

and one line in `app()`:

```rust
app.api::<Note>("/api/notes");
```

That's a complete REST API. Restart the server, then try it from another terminal:

```sh
# Create a note: 201 Created, with the id chosen by the database
curl -X POST http://localhost:3000/api/notes \
  -H 'content-type: application/json' \
  -d '{"text": "Learn Rust", "done": false}'

# List the notes
curl http://localhost:3000/api/notes

# Mark note 1 as done (PATCH changes only the fields you send)
curl -X PATCH http://localhost:3000/api/notes/1 \
  -H 'content-type: application/json' \
  -d '{"done": true}'

# Delete it: 204 No Content
curl -X DELETE http://localhost:3000/api/notes/1
```

What happened:

- `#[model]` turned the struct into a database table named `note`, with typed columns. The `id` field is the primary key, generated by the database. The struct can also be converted to and from JSON.
- At startup, `app.api::<Note>(...)` created the table (it didn't exist yet) and added six routes: list, read, create, replace, update and delete. See [REST API](rest-api.md).
- The database is in memory for now: stop the server and the notes are gone. Step 7 fixes that.

## 6. Show the notes on the page, with a form

Replace `home` with a version that reads the notes, and add a handler for the form:

```rust
/// The data sent by the "new note" form.
#[data]
struct NewNote {
    text: String,
}

/// The home page: the form and the list of notes.
async fn home(req: Request) -> Result<Page> {
    let notes = Note::query().order_by(Note::ID.desc()).all(req.db()).await?;
    Ok(Page::new("Notebook")
        .description("My notes, in Rust.")
        .body(
            html::main()
                .child(h1().text("📒 Notebook"))
                .child(
                    form()
                        .attr("method", "post")
                        .attr("action", "/notes")
                        .class("row")
                        .child(input().attr("name", "text").attr("placeholder", "A new note"))
                        .child(button().text("Add")),
                )
                .child(ul().children(notes.into_iter().map(|note| li().text(note.text)))),
        ))
}

/// Saves the note sent by the form, then goes back to the home page.
async fn add_note(req: Request) -> Result<Redirect> {
    let form: NewNote = req.form().await?;
    let mut note = Note { id: 0, text: form.text, done: false };
    note.insert(req.db()).await?;
    Ok(Redirect::see_other("/"))
}
```

Register the form's route in `app()`:

```rust
app.post("/notes", add_note);
```

Restart, add a few notes with the form, and see them appear. A few new things:

- `req.db()` gives the handler the database. `Note::query()...all(req.db()).await?` reads every note, newest first. The column names (`Note::ID`) are checked by the compiler.
- `#[data]` marks a struct that only travels as data (a form, a JSON body), without a table.
- The handlers now return `Result<...>`. The `?` after a database call or `req.form()` stops the handler on error and sends the right HTTP status: `400` for an invalid form, `404` for a missing row, `500` for a server problem. See [Errors](errors.md).
- `Redirect::see_other("/")` sends the browser back to the home page after the form is posted, the classic "post, redirect, get" pattern.
- The form needs no CSRF token: the security shield already refuses forms posted from other websites. See [Security](security.md).

## 7. Keep the data

The database comes from the `DATABASE_URL` environment variable. Point it to a SQLite file:

```sh
DATABASE_URL=sqlite://notebook.db paquets dev
```

The startup line now says `database: sqlite`. The file `notebook.db` is created next to `Cargo.toml`, the `note` table is created in it, and your notes survive restarts. On Windows PowerShell, write `$env:DATABASE_URL="sqlite://notebook.db"; paquets dev`.

Want a first note in an empty database? Add this to `app()`, before `app`:

```rust
app.on_start(|db| async move {
    if Note::count(db).await? == 0 {
        Note { id: 0, text: "Try Paquets".into(), done: false }.insert(db).await?;
    }
    Ok(())
});
```

`on_start` runs once, when the database is ready and the tables exist, before the first request. In production on Heroku, `DATABASE_URL` points to PostgreSQL and the same code works unchanged. See [Database](database.md).

## 8. Test it

Add this at the end of `src/main.rs`:

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[tokio::test]
    async fn the_form_adds_a_note() {
        let client = app().test().await;

        let res = client.post("/notes").form(&[("text", "Write a test")]).await;
        assert_eq!(res.status(), 303);

        let html = client.get("/").await.text();
        assert!(html.contains("Try Paquets"));
        assert!(html.contains("Write a test"));
    }
}
```

Run the tests:

```sh
cargo test
```

`app().test().await` starts your real app, with its routes, its security and its `on_start` hook, without opening a port. The database is in memory and empty for each test, whatever `DATABASE_URL` says, so tests never touch your data. See [Testing](testing.md).

## The complete program

```rust
use paquets::prelude::*;

/// A note: a table of the database, also sent and received as JSON.
#[model]
struct Note {
    id: i64,
    text: String,
    done: bool,
}

/// The data sent by the "new note" form.
#[data]
struct NewNote {
    text: String,
}

/// The home page: the form and the list of notes.
async fn home(req: Request) -> Result<Page> {
    let notes = Note::query().order_by(Note::ID.desc()).all(req.db()).await?;
    Ok(Page::new("Notebook")
        .description("My notes, in Rust.")
        .body(
            html::main()
                .child(h1().text("📒 Notebook"))
                .child(
                    form()
                        .attr("method", "post")
                        .attr("action", "/notes")
                        .class("row")
                        .child(input().attr("name", "text").attr("placeholder", "A new note"))
                        .child(button().text("Add")),
                )
                .child(ul().children(notes.into_iter().map(|note| li().text(note.text)))),
        ))
}

/// Saves the note sent by the form, then goes back to the home page.
async fn add_note(req: Request) -> Result<Redirect> {
    let form: NewNote = req.form().await?;
    let mut note = Note { id: 0, text: form.text, done: false };
    note.insert(req.db()).await?;
    Ok(Redirect::see_other("/"))
}

fn app() -> App {
    let mut app = App::new();
    app.get("/", home);
    app.post("/notes", add_note);
    app.get("/hello/:name", |req: Request| async move {
        format!("Hello {}!", req.param("name").unwrap_or("you"))
    });
    app.api::<Note>("/api/notes");
    app.on_start(|db| async move {
        if Note::count(db).await? == 0 {
            Note { id: 0, text: "Try Paquets".into(), done: false }.insert(db).await?;
        }
        Ok(())
    });
    app
}

fn main() -> std::io::Result<()> {
    app().run()
}

#[cfg(test)]
mod tests {
    use super::*;

    #[tokio::test]
    async fn the_form_adds_a_note() {
        let client = app().test().await;

        let res = client.post("/notes").form(&[("text", "Write a test")]).await;
        assert_eq!(res.status(), 303);

        let html = client.get("/").await.text();
        assert!(html.contains("Try Paquets"));
        assert!(html.contains("Write a test"));
    }
}
```

## 9. Put it online

Your project already contains everything needed to deploy it: a `Dockerfile`, the files for Heroku and the GitHub workflows. Push it to a GitHub repository, then follow [Deploy to Heroku from your phone](deploy-heroku-mobile.md): a few taps, no computer required.
