# REST API

`app.api::<Model>(path)` gives a model a complete JSON API in one line: list, read, create, replace, update and delete, with pagination, the right status codes and clear errors. This page describes each route, shows how to call them, and how to protect or extend the API.

## One line

```rust
use paquets::prelude::*;

#[model]
struct Todo {
    id: i64,
    title: String,
    done: bool,
}

fn main() -> std::io::Result<()> {
    let mut app = App::new();
    app.api::<Todo>("/api/todos");
    app.run()
}
```

This line creates the `todo` table at startup (if it doesn't exist yet) and adds six routes:

| Request | Effect | Success |
|---|---|---|
| `GET /api/todos` | lists the rows, in key order, 100 at a time | `200`, JSON array, total in `X-Total-Count` |
| `GET /api/todos/:id` | reads one row | `200`, JSON object |
| `POST /api/todos` | creates a row from the JSON body | `201 Created`, the row with its generated `id` |
| `PUT /api/todos/:id` | replaces the whole row | `200`, the row |
| `PATCH /api/todos/:id` | changes only the fields present in the body | `200`, the row |
| `DELETE /api/todos/:id` | deletes the row | `204 No Content` |

## Calling the API

The examples use `curl` against a server running on port 3000.

### Create

```sh
curl -X POST http://localhost:3000/api/todos \
  -H 'content-type: application/json' \
  -d '{"title": "Write docs", "done": false}'
```

```http
HTTP/1.1 201 Created
content-type: application/json

{"id":1,"title":"Write docs","done":false}
```

The `id` is generated by the database. If the body contains an `id`, it is ignored. Every other field is required, unless it is an `Option` or has `#[serde(default)]` (see [Database](database.md#optional-fields-in-json)).

### List

```sh
curl -i 'http://localhost:3000/api/todos?limit=20&offset=40'
```

```http
HTTP/1.1 200 OK
content-type: application/json
x-total-count: 57

[{"id":41,"title":"...","done":false}, ...]
```

| Query parameter | Default | Meaning |
|---|---|---|
| `limit` | `100` | how many rows to return, between 1 and 1000 (larger values are capped at 1000) |
| `offset` | `0` | how many rows to skip |

Rows are always sorted by primary key. The `X-Total-Count` header holds the total number of rows, so a client can compute the number of pages: `ceil(total / limit)`.

### Read one

```sh
curl http://localhost:3000/api/todos/1
```

```json
{"id":1,"title":"Write docs","done":false}
```

### Replace

`PUT` sends the whole row. The `id` comes from the URL:

```sh
curl -X PUT http://localhost:3000/api/todos/1 \
  -H 'content-type: application/json' \
  -d '{"title": "Write better docs", "done": true}'
```

### Update some fields

`PATCH` sends only the fields to change. The others keep their value:

```sh
curl -X PATCH http://localhost:3000/api/todos/1 \
  -H 'content-type: application/json' \
  -d '{"done": true}'
```

```json
{"id":1,"title":"Write better docs","done":true}
```

### Delete

```sh
curl -X DELETE http://localhost:3000/api/todos/1   # 204 No Content
```

## Errors

Every error is a JSON object with an `error` message:

| Situation | Status | Body |
|---|---|---|
| The `id` in the URL is not valid for the key type (`/api/todos/abc`) | `400` | ``{"error":"invalid id `abc`"}`` |
| `limit` or `offset` is not a positive integer | `400` | ``{"error":"`limit` must be a positive integer"}`` |
| Invalid JSON, missing field, wrong type | `400` | ``{"error":"invalid JSON: missing field `done` at line 1 column 22"}`` (for `{"title":"Write docs"}`) |
| `PATCH` with a body that is not a JSON object | `400` | `{"error":"expected a JSON object"}` |
| No row with this `id` (`GET`, `PUT`, `PATCH`, `DELETE`) | `404` | `{"error":"record not found"}` |
| A `unique` column already has this value | `409` | ``{"error":"unique constraint violated on `member.email`"}`` |
| A server problem (database unreachable…) | `500` | `{"error":"Internal Server Error"}`, details in the logs |

## Keys

The primary key can be any type that can be read from a URL:

- an integer `id` (the usual case), generated by the database;
- a `String` chosen by the client, marked `#[memoire(primary_key)]`: `/api/tags/rust`;
- a `uuid::Uuid` (feature `uuid`).

```rust
#[model(table = "tags")]
struct Tag {
    #[memoire(primary_key)]
    slug: String,
    label: String,
}

app.api::<Tag>("/api/tags"); // POST {"slug": "rust", "label": "Rust"}, then GET /api/tags/rust
```

A string or UUID key is not generated: the client must send it in `POST` bodies.

## Several APIs

Call `app.api` once per model. Each one gets its own table and routes:

```rust
app.api::<Todo>("/api/todos");
app.api::<Tag>("/api/tags");
app.api::<Member>("/api/members");
```

You can't declare your own route on the same method and path as an `app.api` route (for example your own `GET /api/todos`): the app panics at startup with `duplicate route`. Other paths are free, such as `GET /api/todos/stats`.

## Protecting the API

The routes of `app.api` are public: anyone can create or delete rows. That's fine for a prototype, rarely for production. The shield already blocks attacks, floods and cross-site forms, but it doesn't know who your users are. Add a middleware that checks something only your clients have, for every request that changes data:

```rust
async fn require_token(req: Request, next: Next) -> Response {
    let writes = req.method() != Method::GET && req.method() != Method::HEAD;
    if req.path().starts_with("/api/") && writes {
        let expected = std::env::var("API_TOKEN").unwrap_or_default();
        let sent = req.header("authorization").and_then(|h| h.strip_prefix("Bearer "));
        if expected.is_empty() || sent != Some(expected.as_str()) {
            return Error::unauthorized("missing or wrong token").into_response();
        }
    }
    next.run(req).await
}

app.middleware(require_token);
app.api::<Todo>("/api/todos");
```

Reading stays public, and writing needs `Authorization: Bearer <token>`, where the token is the `API_TOKEN` environment variable (a config var on Heroku). For accounts and sessions, see [Security](security.md#authentication).

## When to write your own routes

`app.api` is a generic CRUD. It doesn't validate values beyond their types, filter lists, hide fields, or check who owns a row. As soon as you need rules, write the routes yourself: it's a few lines with the [database](database.md) API.

```rust
#[data]
struct NewTodo {
    title: String,
}

async fn create_todo(req: Request) -> Result<(StatusCode, Json<Todo>)> {
    let new: NewTodo = req.json().await?;
    let title = new.title.trim();
    if title.is_empty() || title.len() > 200 {
        return Err(Error::unprocessable("the title must have 1 to 200 characters"));
    }
    let mut todo = Todo { id: 0, title: title.to_string(), done: false };
    todo.insert(req.db()).await?;
    Ok((StatusCode::CREATED, Json(todo)))
}

async fn search_todos(req: Request) -> Result<Json<Vec<Todo>>> {
    let q = req.query("q").unwrap_or_default().to_string();
    let todos = Todo::query()
        .filter(Todo::TITLE.icontains(q))
        .order_by(Todo::ID.asc())
        .limit(50)
        .all(req.db())
        .await?;
    Ok(Json(todos))
}

app.model::<Todo>(); // the table, without the generic routes
app.post("/api/todos", create_todo);
app.get("/api/todos/search", search_todos);
```

## Calling the API from a browser

A page of your own site can call the API with `fetch`: the request comes from the same origin, so the shield lets it through. A front end hosted on **another** origin (another domain, or a development server on another port) needs two changes to the shield: CORS, so that the browser lets the page read the responses, and a trusted origin for the CSRF guard, so that its `POST`, `PUT`, `PATCH` and `DELETE` requests are accepted:

```rust
use paquets::securite::prelude::*;

app.security(
    paquets::shield()
        .guard(Cors::new().allow_origin("https://app.example.com"))
        .guard(Csrf::new().trusted_origin("https://app.example.com"))
        .build(),
);
```

See [Security](security.md#changing-the-shield).

## Testing the API

```rust
#[tokio::test]
async fn creates_and_lists_todos() {
    let mut app = App::new();
    app.api::<Todo>("/api/todos");
    let client = app.test().await;

    let res = client
        .post("/api/todos")
        .json(&json!({ "title": "Write docs", "done": false }))
        .await;
    assert_eq!(res.status(), 201);
    let created: Todo = res.json();
    assert_eq!(created.id, 1);

    let res = client.get("/api/todos").await;
    assert_eq!(res.header("x-total-count"), Some("1"));
    assert_eq!(res.json::<Vec<Todo>>().len(), 1);

    assert_eq!(client.get("/api/todos/99").await.status(), 404);
}
```
