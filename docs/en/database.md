# Database

Paquets stores data with [memoire-orm](https://github.com/maxlestage/Memoire), a type-safe ORM: a Rust struct describes a table, and queries are written in Rust, checked by the compiler. The same code runs in memory, on SQLite, PostgreSQL, MySQL/MariaDB, Redis or MongoDB: the database is chosen by a URL. This page covers models, choosing the database, reading and writing, transactions, schema changes and raw SQL.

## Models

A model is a struct marked with `#[model]`:

```rust
use paquets::prelude::*;

#[model]
struct Todo {
    id: i64,      // the primary key, generated by the database
    title: String,
    done: bool,
}
```

`#[model]` makes the struct a database table **and** a JSON value. It adds `#[derive(Clone, Debug, Serialize, Deserialize, Model)]` (derives you already wrote are kept) and points the generated code to the crates re-exported by Paquets, so you need no other dependency.

| Rule | Details |
|---|---|
| Table name | the struct name in `snake_case`, not pluralised: `Todo` → `todo`, `BlogPost` → `blog_post`. Choose another name with `#[model(table = "todos")]`. |
| Primary key | the field named `id`. An integer `id` (`i64`, `i32` or `i16`) is generated by the database when a row is inserted. |
| `id` in JSON | an integer `id` may be omitted in JSON bodies: clients creating a row don't know it yet. |
| Columns | one per field, with the same name. `Option<T>` makes a column nullable; every other column is `NOT NULL`. |
| Typed columns | each field gets a constant in `UPPER_SNAKE_CASE`, used in queries: `Todo::TITLE`, `Todo::DONE`. |

### Column types

| Rust type | Notes |
|---|---|
| `bool` | |
| `i16`, `i32`, `i64` (and `i8`, `u8`, `u16`, `u32`) | `u64`, `usize` and `i128` are not supported: use `i64` |
| `f32`, `f64` | |
| `String` | |
| `Vec<u8>` | binary data |
| `Option<T>` | any of the above, nullable |
| `chrono::NaiveDateTime`, `DateTime<Utc>`, `NaiveDate`, `NaiveTime` | feature `chrono` |
| `uuid::Uuid` | feature `uuid` |
| `serde_json::Value`, `Json<T>` | feature `json` |

### Column attributes

memoire's attributes work on fields, inside `#[memoire(...)]`:

```rust
#[model(table = "users")]
struct User {
    id: i64,
    #[memoire(unique)]
    email: String,
    #[memoire(index)]
    name: String,
    #[memoire(default = "0")]
    visits: i32,
    bio: Option<String>,
}
```

| Attribute | Effect |
|---|---|
| `#[memoire(unique)]` | a second row with the same value is refused: `409 Conflict` in a handler |
| `#[memoire(index)]` | an index, for columns you filter or sort by often |
| `#[memoire(column = "e_mail")]` | another name for the column |
| `#[memoire(default = "0")]` | a SQL default, used when you add the column to an existing table |
| `#[memoire(references = "users(id)", on_delete = "cascade")]` | a foreign key |
| `#[memoire(primary_key)]` | another field as the primary key, for example a `slug: String` |
| `#[memoire(skip)]` | a field that is not stored (its type must implement `Default`) |

### Optional fields in JSON

A `bool` or `String` field is required in JSON bodies. To let clients omit it, add `#[serde(default)]` (the field then gets `false`, `0` or an empty string), or make it an `Option`:

```rust
#[model]
struct Task {
    id: i64,
    title: String,
    #[serde(default)]
    done: bool,          // may be omitted: false
    due: Option<String>, // may be omitted or null: NULL in the database
}
```

## Choosing the database

The database is chosen by the `DATABASE_URL` environment variable when the app starts:

| `DATABASE_URL` | Database | Cargo feature |
|---|---|---|
| *(not set)* or `memory` | in memory, emptied when the server stops | always available |
| `sqlite://app.db`, `app.db`, `sqlite::memory:` | a SQLite file, created if missing | `sqlite` (default) |
| `postgres://user:password@host:5432/name` | PostgreSQL, with TLS when the server offers it | `postgres` (default) |
| `mysql://…`, `mariadb://…` | MySQL or MariaDB | `mysql` |
| `redis://…`, `rediss://…` | Redis | `redis` |
| `mongodb://…`, `mongodb+srv://…` | MongoDB | `mongodb` |

```sh
DATABASE_URL=sqlite://app.db paquets dev
```

The startup line tells you which one is used: `database: sqlite`. On Heroku, adding the Heroku Postgres add-on sets `DATABASE_URL` for you: nothing to change in the code.

You can also choose the database in the code. It then wins over `DATABASE_URL`:

```rust
let mut app = App::new();
app.database("sqlite://app.db"); // a file next to where the program runs
// or: app.database(Db::memory());
```

If the URL is wrong or the server can't be reached, the app doesn't start, and says why. A URL that needs a feature you didn't enable even tells you what to write in `Cargo.toml`:

```text
📦 Paquets could not start: database: operation not supported by this backend: `mysql` URLs need the `mysql` feature: paquets = { version = "0.1", features = ["mysql"] }
```

> [!NOTE]
> Tests created with `app.test()` always use a fresh in-memory database, unless the test itself calls `app.database(...)`. `DATABASE_URL` is ignored there, so tests never touch your data.

## Tables are created at startup

When the app starts, it creates the table of every model registered with `app.api::<M>(...)` (see [REST API](rest-api.md)) or `app.model::<M>()`, **if the table doesn't exist yet**. Use `app.model` for models you only use in your own handlers:

```rust
let mut app = App::new();
app.api::<Todo>("/api/todos"); // table + REST routes
app.model::<User>();            // table only
```

An existing table is never changed: when you add a field to a model later, see [Changing a table later](#changing-a-table-later).

## Reading data

In a handler, `req.db()` returns the database. Every model method takes it as its first argument:

```rust
async fn show(req: Request) -> Result<Json<Todo>> {
    let id: i64 = req.param_as("id")?;          // 400 if not a number
    let todo = Todo::get(req.db(), id).await?; // 404 if there is no such row
    Ok(Json(todo))
}
```

| Code | Returns |
|---|---|
| `Todo::all(db).await?` | `Vec<Todo>`: every row |
| `Todo::get(db, id).await?` | `Todo`, or a "not found" error (`404` in a handler) |
| `Todo::find(db, id).await?` | `Option<Todo>` |
| `Todo::count(db).await?` | `u64` |
| `todo.reload(db).await?` | refreshes a struct from the database |

### Queries

`Todo::query()` starts a query. Chain filters, ordering and limits, then run it:

```rust
async fn open_todos(req: Request) -> Result<Json<Vec<Todo>>> {
    let todos = Todo::query()
        .filter(Todo::DONE.eq(false))
        .filter(Todo::TITLE.contains("docs"))
        .order_by(Todo::ID.desc())
        .limit(20)
        .all(req.db())
        .await?;
    Ok(Json(todos))
}
```

The column constants are typed: `Todo::DONE.eq("yes")` doesn't compile, because `done` is a `bool`.

| Filter | Code |
|---|---|
| equal, not equal | `Todo::DONE.eq(false)`, `.ne(false)` |
| comparisons | `User::VISITS.gt(10)`, `.ge(10)`, `.lt(10)`, `.le(10)` |
| and, or, not | `a & b`, `a \| b`, `!a`, or several `.filter(...)` calls (and) |
| in a list | `Todo::ID.is_in([1, 2, 3])` |
| between | `User::VISITS.between(1, 10)` |
| null | `User::BIO.is_null()`, `.is_not_null()` |
| text | `.contains("x")`, `.starts_with("x")`, `.ends_with("x")`, `.icontains("x")` (any case), `.like("%x%")` |

| Run with | Returns |
|---|---|
| `.all(db)` | `Vec<Todo>` |
| `.first(db)` | `Option<Todo>` |
| `.one(db)` | `Todo`, or "not found" |
| `.count(db)` | `u64` |
| `.exists(db)` | `bool` |
| `.paginate(db, page, per_page)` | a page of results: `items`, `page`, `per_page` and `total` |
| `.columns(Todo::TITLE).all(db)` | `Vec<String>`: only that column |

Ordering and paging: `.order_by(Todo::TITLE)` (ascending), `.order_by(Todo::ID.desc())`, `.limit(20)`, `.offset(40)`, `.page(3, 20)`.

A paginated list in a page:

```rust
async fn todo_list(req: Request) -> Result<Page> {
    let page: u64 = req.query("page").and_then(|p| p.parse().ok()).unwrap_or(1);
    let result = Todo::query().order_by(Todo::ID.asc()).paginate(req.db(), page, 20).await?;
    Ok(Page::new(format!("Todos, page {page}")).body(
        section()
            .child(p().class("muted").text(format!("{} todos in total", result.total)))
            .child(ul().children(result.items.into_iter().map(|t| li().text(t.title)))),
    ))
}
```

The value returned by `paginate` is memoire's own `Page` type (`paquets::orm::Page`), not the HTML `Page`: you only use its fields.

## Writing data

```rust
// Insert: the struct must be `mut`, the generated id is written back into it.
let mut todo = Todo { id: 0, title: "Write docs".into(), done: false };
todo.insert(db).await?;
println!("new id: {}", todo.id);

// Update every column of the row with this id ("not found" if it doesn't exist).
todo.done = true;
todo.update(db).await?;

// Delete: `true` if a row was deleted.
let deleted: bool = Todo::delete_by_key(db, todo.id).await?;
```

| Code | Effect |
|---|---|
| `row.insert(db)` | inserts the row and writes the generated `id` back |
| `Todo::insert_many(db, &rows)` | inserts several rows, returns how many |
| `row.upsert(db)` | inserts, or replaces the row with the same key |
| `row.update(db)` | saves every column of the row |
| `row.delete(db)` | deletes the row, returns `bool` |
| `Todo::delete_by_key(db, id)` | deletes by key, returns `bool` |
| `Todo::update_many().set(Todo::DONE, true).filter(...).execute(db)` | updates many rows, returns how many |
| `Todo::delete_many().filter(...).execute(db)` | deletes many rows, returns how many |

`update_many` also has `.increment(column, n)`, `.decrement(column, n)` and `.set_null(column)`.

## Transactions

A transaction groups several changes: either all of them are saved, or none. Start one with `db.begin()`, pass `&tx` instead of the database, then `commit`:

```rust
#[model]
struct Account {
    id: i64,
    balance: i64,
}

#[data]
struct Transfer {
    from: i64,
    to: i64,
    amount: i64,
}

async fn transfer(req: Request) -> Result<StatusCode> {
    let t: Transfer = req.json().await?;
    let tx = req.db().begin().await?;
    Account::update_many()
        .decrement(Account::BALANCE, t.amount)
        .filter(Account::ID.eq(t.from))
        .execute(&tx)
        .await?;
    Account::update_many()
        .increment(Account::BALANCE, t.amount)
        .filter(Account::ID.eq(t.to))
        .execute(&tx)
        .await?;
    tx.commit().await?;
    Ok(StatusCode::NO_CONTENT)
}
```

If anything fails before `commit` (a `?` returns early), the transaction is dropped and every change is rolled back.

## Data at startup

`app.on_start` runs once, after the database is open and the tables exist, before the first request. Use it to add initial data:

```rust
app.on_start(|db| async move {
    if Todo::count(db).await? == 0 {
        Todo { id: 0, title: "Try Paquets".into(), done: false }.insert(db).await?;
    }
    Ok(())
});
```

If the hook returns an error, the app doesn't start, and the message begins with `startup:`. You can call `on_start` several times: hooks run in order.

## Changing a table later

Tables are created when they are missing, but **never altered**. If you add a field to a model whose table already exists (in a SQLite file or on Heroku Postgres), the column is missing, and queries on that model fail with a `500`. With the in-memory database (development, tests) there is nothing to do: the table is recreated at every start.

For an existing database, use a **migration**: a numbered change, recorded in the database so that it runs only once. memoire's `Migrator` does this, and `on_start` is the place to run it. This example adds a `priority` column to the `todo` table on PostgreSQL:

```rust
use paquets::orm::{Dialect, Migration, Migrator};

app.on_start(|db| async move {
    Migrator::new()
        .add(Migration::new(1, "add_todo_priority").sql_for(
            Dialect::Postgres,
            "ALTER TABLE todo ADD COLUMN IF NOT EXISTS priority INTEGER NOT NULL DEFAULT 0",
        ))
        .run(db)
        .await?;
    Ok(())
});
```

Then add `priority: i32` to the struct. How it works, and the rules to follow:

- `sql_for(Dialect::Postgres, ...)` runs only on PostgreSQL; it is skipped on the in-memory database, so your tests keep working. There are also `Dialect::Sqlite` and `Dialect::MySql`, and `.sql(...)` for every SQL database.
- `IF NOT EXISTS` makes the change safe on a brand-new database too: there, the table was just created from the current struct and already has the column.
- Never change a migration that already ran somewhere: add a new one with the next number.
- Don't `create_table::<M>()` in these migrations for a model registered with `app.api` or `app.model`: its table was already created before `on_start` runs, and the migration would fail with "table already exists".

> [!NOTE]
> SQLite and MySQL don't support `ADD COLUMN IF NOT EXISTS`. For them, run the migrations yourself **before** the app creates its tables: open the database with `Db::connect(&url).await?`, run the `Migrator` (with `create_table` steps built from frozen copies of your structs), then hand the database to the app with `app.database(db)` and start it with `app.serve().await` inside `#[tokio::main]`. memoire's [migrations guide](https://github.com/maxlestage/Memoire/blob/master/docs/en/migrations.md) explains frozen structs in detail.

## Raw SQL

When the query builder isn't enough, write SQL. Placeholders are `?` on SQLite and MySQL, `$1`, `$2`… on PostgreSQL. Rows are decoded by position, into tuples or structs:

```rust
use paquets::orm::params;

async fn top_visitors(req: Request) -> Result<Json<Vec<(i64, String)>>> {
    let rows: Vec<(i64, String)> = req
        .db()
        .raw("SELECT id, name FROM users WHERE visits > ? ORDER BY visits DESC", &params![10])
        .await?;
    Ok(Json(rows))
}
```

`db.raw_execute(sql, &params![...])` runs a statement that returns no rows and gives the number of affected rows. Raw SQL works on SQLite, PostgreSQL and MySQL; the in-memory database, Redis and MongoDB return an "unsupported" error.

## Errors

Database errors become HTTP statuses when they reach a handler through `?`:

| Error | Status |
|---|---|
| no such row (`get`, `one`, `update`) | `404 Not Found`: `{"error":"record not found"}` |
| duplicate value in a `unique` column | `409 Conflict`: ``{"error":"unique constraint violated on `user.email`"}`` |
| other constraint (foreign key…), transaction conflict | `409 Conflict` |
| `NULL` in a non-`Option` field, invalid value | `400 Bad Request` |
| anything else (connection lost, missing table or column…) | `500 Internal Server Error`; the details go to the server logs, never to the client |

To react to an error yourself instead, match on it before `?`: `Todo::find` returns `None` instead of an error, and memoire's errors have `is_not_found()`, `is_unique_violation()` and `is_conflict()`. See [Errors](errors.md).

## Which database should I use?

| Situation | Choice |
|---|---|
| Learning, prototypes, tests | in memory (nothing to set) |
| One server with a disk that persists (a VPS, a Raspberry Pi, a Docker volume) | SQLite: one file, nothing to install, very fast |
| Heroku, or several servers | PostgreSQL |
| An existing database | the one you have: MySQL/MariaDB, Redis or MongoDB |

> [!WARNING]
> Don't use SQLite on Heroku: the file system of a dyno is temporary, and the file is lost at every deployment and restart (at least once a day). Add the Heroku Postgres add-on instead (see [Deploy to Heroku](deploy-heroku-mobile.md#2-add-a-database)).

With PostgreSQL, the pool opens up to 4 connections per CPU core when the traffic needs them. Small hosted plans limit connections (often to 20): to choose the pool size yourself, open the pool with memoire (`PgPool::connect_with(&url, 10)`), and pass it with `app.database(Db::from(pool))` from an async `main` (see [Configuration](configuration.md#async-initialisation)).
