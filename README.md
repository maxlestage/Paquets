# 📦 Paquets

**The simplest full-stack framework for Rust.**

Server, security, database, REST API, SEO pages and WebAssembly islands: one crate, one import, one `App`.

```rust,no_run
use paquets::prelude::*;

#[model]
struct Todo {
    id: i64,
    title: String,
    done: bool,
}

fn main() -> std::io::Result<()> {
    let mut app = App::new();

    app.get("/", |_| async {
        Page::new("Home").body(h1().text("Hello 👋"))
    });
    app.api::<Todo>("/api/todos"); // GET, POST, PUT, PATCH, DELETE

    app.run() // http://localhost:3000, or $PORT on Heroku
}
```

That's a complete web app: a server-rendered page with its SEO tags, a REST API stored in a
database, and a security shield in front of every request. Nothing to configure.

## Why Paquets

| | |
|---|---|
| ✨ **Simple** | `use paquets::prelude::*;`, `App::new()`, `app.run()`. Handlers are `async` functions; `?` works on every error and picks the right HTTP status. |
| 🛡️ **Secure by default** | WAF (SQL injection, XSS, RCE, Log4Shell…), rate limiting, CSRF, security headers, request ids, bot blocker. Pages send a Content-Security-Policy that allows exactly their own inline code. |
| 🗄️ **Any database** | In memory, SQLite, PostgreSQL, MySQL/MariaDB, Redis, MongoDB, chosen by `DATABASE_URL`. `#[model]` gives you typed queries and a REST API in one line. |
| 🔎 **SEO pages** | Pages are finished HTML from the server: title, description, Open Graph, Twitter, canonical, JSON-LD. A built-in theme (light and dark) makes them look good without CSS. |
| 📲 **Installable (PWA)** | `app.pwa(Pwa::new("My app"))`: a web app manifest and an offline service worker, so the app goes on the home screen and keeps working without network. |
| 🏝️ **Islands** | The interactive parts are Rust components compiled to WebAssembly, and only those: the rest of the page ships no code. |
| ⚡ **Fast** | Built on a server faster than actix-web and axum, a security pipeline of ≈ 6 µs, compile-time SQL. |
| 📱 **Deploy from your phone** | Dockerfile, `heroku.yml`, `app.json` and GitHub Actions are generated: one tap on *Deploy to Heroku*. |

## Four packages, one framework

Paquets assembles four crates, each usable on its own:

| Package | Role | In Paquets |
|---|---|---|
| [**Vitesse**](https://maxlestage.github.io/Vitesse/) | HTTP server in the style of Express: routes, middlewares, routers, WebSocket, sessions, HTTPS, HTTP/2 and HTTP/3 | `App` (dereferences to `vitesse::App`), `Request`, `Json`, `Router`… |
| [**Securite**](https://maxlestage.github.io/Securite/) | Security middlewares: WAF, rate limit, CSRF, CORS, headers & CSP, auth… | in front of every request, `app.security(...)` |
| [**memoire-orm**](https://maxlestage.github.io/Memoire/) | Type-safe async ORM with compile-time SQL, SQL and NoSQL, relations and full-text search | `#[model]`, `req.db()`, `app.api::<M>()` |
| [**active**](https://maxlestage.github.io/Active/) | Front end: components, state, server rendering, SEO, WebAssembly islands | `Page`, `div()`, `h1()`, `island(...)`, `use_state` |

## Get started

```sh
cargo install --git https://github.com/maxlestage/Paquets paquets --locked    # the `paquets` command
paquets new my-app                # a complete project, ready to deploy
cd my-app
paquets dev                       # http://localhost:3000
```

`paquets new` creates the server (`src/main.rs`: pages, a model and its API), the browser
components (`src/lib.rs`: an island), a `Dockerfile`, Heroku files, and GitHub Actions that test
every push and **merge every green branch into `master` automatically**. `paquets build` makes
the release build, `paquets doctor` checks your tools.

Or add Paquets to an existing project:

```toml
[dependencies]
paquets = { git = "https://github.com/maxlestage/Paquets" }
```

## A tour

```rust
use paquets::prelude::*;

#[model]                         // a table, and JSON in and out
struct Todo {
    id: i64,                     // primary key, generated by the database
    title: String,
    done: bool,
}

/// A page, rendered on the server.
async fn home(req: Request) -> Result<Page> {
    let todos = Todo::query()
        .filter(Todo::DONE.eq(false))
        .order_by(Todo::ID.asc())
        .all(req.db())
        .await?;
    Ok(Page::new("To do")
        .description("What is left to do.")
        .body(h1().text("To do"))
        .body(ul().children(todos.into_iter().map(|t| li().text(t.title)))))
}

/// JSON, with errors that become the right status.
async fn show(req: Request) -> Result<Json<Todo>> {
    let id: i64 = req.param_as("id")?;          // 400 if `id` is not a number
    let todo = Todo::get(req.db(), id).await?; // 404 if there is no such row
    Ok(Json(todo))
}

fn app() -> App {
    let mut app = App::new();
    app.get("/", home);
    app.get("/todos/:id", show);
    app.api::<Todo>("/api/todos");
    app
}

#[tokio::test]
async fn it_works() {
    let client = app().test().await;            // no port, database in memory
    let res = client
        .post("/api/todos")
        .json(&json!({ "title": "Try Paquets", "done": false }))
        .await;
    assert_eq!(res.status(), 201);
    assert!(client.get("/").await.text().contains("Try Paquets"));
}
```

## Deploy from your phone

1. Open `https://heroku.com/deploy?template=https://github.com/maxlestage/Paquets` on your phone,
   choose an app name, tap **Deploy app**. Heroku reads [`app.json`](app.json) and builds the
   [`Dockerfile`](Dockerfile): the website, which is itself a Paquets app, with its live demo
   (`/demo`, `/api/todos`).
2. Automatic deploys of `master`: in GitHub, *Settings → Secrets and variables → Actions*, add the
   secret `HEROKU_API_KEY` (Heroku → *Account settings* → *API Key*) and the variable
   `HEROKU_APP_NAME`. [`heroku.yml`](.github/workflows/heroku.yml) then deploys every merge.
3. A database: Heroku → your app → *Resources* → *Heroku Postgres*. Its `DATABASE_URL` is used
   automatically.

Heroku has no free plan (an Eco dyno costs about $5 a month). Projects created with
`paquets new` contain the same files. Step-by-step guide:
[docs/en/deploy-heroku-mobile.md](docs/en/deploy-heroku-mobile.md).

The website is also published for free on **GitHub Pages** at
<https://maxlestage.github.io/Paquets/> ([`pages.yml`](.github/workflows/pages.yml); one-time setup:
*Settings → Pages → Source: GitHub Actions*).

## Always merged into master

Every push runs the [CI](.github/workflows/ci.yml): format, clippy (server, browser and every
feature), tests, documentation, MSRV, the projects generated by `paquets new`, the website. When
everything is green, the branch is **merged into `master` automatically** (except branches named
`wip/...`), then the website and the Heroku app are deployed.

## Publish on crates.io (from your phone)

1. crates.io → *Account Settings* → *API Tokens* → a token with the *publish-new* and
   *publish-update* scopes; add it to GitHub as the secret `CARGO_REGISTRY_TOKEN`.
2. GitHub → *Releases* → *Draft a new release* → tag `v0.1.0` → *Publish release*.

[`release.yml`](.github/workflows/release.yml) publishes `paquets-macros`, then `paquets`. crates.io
only accepts dependencies that are on crates.io, so Vitesse, Securite, memoire-orm and Active are
published first, each from its own repository in the same way; the workflow checks it. Guide:
[docs/en/publish-crates-io.md](docs/en/publish-crates-io.md).

## Development

```sh
cargo test --workspace                     # the crate, the CLI, the examples
cargo run --example todo                   # the demo app on http://localhost:3000
cargo run -- new my-app --path .           # the CLI, with this checkout of Paquets
cd site && cargo run                       # the website, itself a Paquets app (see site/README.md)
```

| Folder | Contents |
|---|---|
| [`src/`](src) | the `paquets` crate (`app.rs`, `db.rs`, `api.rs`, `page.rs`, `shield.rs`, `error.rs`) and the CLI (`main.rs`, `cli/`) |
| [`macros/`](macros) | `#[model]` and `#[data]` (`paquets-macros`) |
| [`examples/`](examples) | `hello` and `todo` (the app deployed on Heroku) |
| [`docs/`](docs) | the documentation, in English, French and Spanish |
| [`site/`](site) | the website: a Paquets app (pages rendered by Active, islands in WebAssembly), exported to static files for GitHub Pages |
